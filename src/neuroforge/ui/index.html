    1Connect a frontier model

    A frontier model proposes the repairs and drafts prompts. Any OpenAI-compatible endpoint works; Poe is the default because one key gives access to hundreds of models. Edits on real models are proposed only by the model you choose here; offline templates exist only for the built-in toy demo.

    Checking the endpoint...

    The list comes from GET /models on your endpoint, filtered to models that reason, with the names your endpoint uses.

    How to change the endpoint or key

    Keys are read only from environment variables and never shown here. Before starting the Studio, set for example POE_API_KEY (Poe), or WEIGHTLAB_LLM_BASE_URL plus WEIGHTLAB_LLM_KEY_ENV for another provider. Run neuroforge doctor to check.

    2Describe the change

    What do you want to change?

    The intent lists prompts where the model fails (and what it should say instead) and prompts where it must not change. Steps 3 to 5 are measured against it.

    Loading the intent...
    What is an intent?

    A short file that says where the model fails (prompts plus the answer you want instead), which prompts must keep their behaviour, and how a fix is scored. The diagnosis, every repair and every check use it.

    Drafting needs a model from step 1. The draft appears in the editor below; review it before saving.

    Validated against the schema when you save. Saved as intent.yaml in the workspace.

          3Diagnose

          Steps 3 and 4 belong to "Fix a failure". In the other modes the preview and the apply button are in step 2; step 5 keeps, undoes or exports every edit.

          Compares the model's internal activity on the failing and passing prompts and ranks the layers that push it toward the failure, with the weight columns most responsible.

          What does "divergence" mean?

          How differently a layer behaves on the failing prompts compared with the passing ones. The layer with the highest score contributes most to the failure; the culprit columns are the weights in that layer most aligned with the failure.

          4Repair

          This step belongs to "Fix a failure".

          Each iteration proposes several candidate edits, measures each one on your prompts, rejects any that break the invariants or the size limits, and commits the best feasible edit to the history. "Goal shortfall" is how far the goals still are (0 means met); "invariant budget used" is the worst change on prompts that must not change, as a share of what your intent allows ("improved" means it got closer to the reference). "Weights targeted" counts the weights the edit script changes; nullspace protection can add a small correction to other entries of the same tensors, which is stored in the patch and counted in the norm checks.

          Model factory

          Specialise the model for one job and measure it on tasks with automatic checks. The factory runs the baseline, a prompt-only baseline (the best system prompt from the suite), a guarded repair on the failing training tasks, and the edited model again. Held-out tasks are never shown to the proposer. Packaging is offered only when the edited model beats both baselines.

          Task suite

          Tasks are checked by Python unit tests or SQL result rows (run in an isolated child process with no network) or by simple text checks. Mark each task with split: train or split: heldout (held-out tasks only measure, they never guide the repair).
